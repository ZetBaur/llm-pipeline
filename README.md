# llm-pipeline

LLM-сервис для обработки сообщений клиентов: summary, ключевые мысли, категория и intent, JSON с валидацией, ответ по категории, многошаговая цепочка с самопроверкой, защита от сбоев. Модель по умолчанию `gpt-4.1-mini` (переменная `OPENAI_MODEL`), ключ в `.env` (`OPENAI_API_KEY`, в git не попадает).

## День 1: базовый пайплайн

- `llm_pipeline/llm_client.py`: единственное место вызова API (`OpenAIChatClient.complete`), считает вызовы и токены. `prompts.py`: промпты отдельно от логики. `pipeline.py`: `run_plain(text, client)` возвращает summary, 3 ключевые мысли и короткий ответ. `main.py`: запуск на `examples/inputs.json` (10 текстов, русские и английские), результат печатается и пишется в `outputs/day1.json`.
- Запуск: `PYTHONPATH=. .venv/bin/python main.py --limit 3`. Три текста обработаны, всего 813 токенов на вход и 294 на выход.
- Замечание: в ответе на первый текст модель добавила совет «не удаляйте приложение», которого в сообщении нет. Мелкая выдумка; её должна ловить самопроверка (день 5).

## День 2: промпты

Три варианта system prompt на одних и тех же 5 текстах, `temperature=0`. Проверка кодом: summary не больше 25 слов, ровно 3 мысли по не больше 12 слов, ответ не больше 40 слов (`scripts/day2_compare_prompts.py`, `outputs/day2_prompt_comparison.json`).

| вариант | что в промпте | соблюдены все ограничения |
|---|---|---|
| `v1_minimal` | только задача и формат | 3 из 5 (summary 26 слов в одном случае, ответ 42 слова в другом) |
| `v2_rules` | + явные числовые лимиты, язык ответа | 5 из 5 |
| `v3_strict` | + пример, запрет выдумывать, «считай слова» | 5 из 5 |

Выбран `v2_rules`: качество то же, что у `v3_strict`, промпт короче (меньше токенов за вызов). Пять текстов и один прогон: различие между v2 и v3 не измерено. Ответы стали короче и стабильнее (summary 11–14 слов, ответ 17–26 слов).
